## ADR-002: Request Validation Strategy and Rejected Payment Handling
### Context
Invalid requests must be rejected with a **Rejected** status without calling the acquiring bank.

### Decisions
1. Implement a dedicated PaymentValidator component rather than use annotation-based Bean validation so multi-field rules (like expiryMonth and expiryYear) and custom ISO currency checks live in a single cohesive unit-testable class.
2. A card expires at the **end** of its expiry month.
3. When validation fails, we return a **400 Bad Request** with a body containing **status: "Rejected"** and some error details and do not persist the rejected request in the database.
