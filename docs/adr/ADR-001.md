## ADR-001: API Contract, JSON Naming, and DTO Separation
### Context
The starter template had a mix of snake_case and camelCase for different JSON fields.
PostPaymentRequest used strictly snake_case @JsonProperty("expiry_month") and mistakenly had a cardNumberLastFour integer field and an integer cvv field.
PostPaymentResponse used camelCase and duplicated GetPaymentResponse.

### Decisions
1. Standardise all JSON payloads on snake_case to match the Acquiring Bank API convention, while using idiomatic camelCase in Java.
2. changed cardNumber and cvv in PostPaymentRequest to String to accept the full 14-19 digit PAN while preserving leading zeros.
3. Masked sensitive PCI data (cardNumber and cvv) in the toString() method.
4. Consolidated the two response DTOs down to a single PaymentResponse DTO.
5. Created dedicated Java 17 records (BankPaymentRequest/Response) to decouple our public merchant contract from the downstream bank contract.
